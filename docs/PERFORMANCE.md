# 性能测量

资源占用是设计目标，以下是可重复执行的本机样本，不是固定占用或稳定版承诺。

## 复现方式

在仓库根目录执行：

```powershell
./scripts/benchmark.ps1 -Offline
./scripts/benchmark.ps1 -Offline -Records 100 -Images
```

默认构建发布版，依次测量 0、100、1000 条文字记录；每个阶段采样 8 秒。带图模式每组最多生成 64 张 640 × 480 的模拟图片。`-Seconds` 可调整到 2–60 秒；`-SkipBuild` 仅在发布 exe 与源码一致时使用。

每个场景创建全新目录，位于 `slint-preview/preview-output/benchmarks/<本次运行>/`，绝不打开正式数据。运行期间会短暂显示模拟小猫与面板，不注册全局快捷键、托盘、OLE 拖放或开机启动。避免在测试窗口上操作鼠标、输入文字，并尽量保持机器负载一致。

输出包含：

- `benchmark.json`：系统、缩放、发布/调试模式、场景和采样汇总。
- `timings.json`：保存、加载、首次模型建立、重开面板回调、离屏渲染、收下及侧栏协调耗时；缩略图解码次数。
- `samples.csv`：每 250 毫秒的工作集、私有内存、CPU 时间和句柄数原始样本。

CPU 百分比以一个逻辑核心满载为 100%，不是任务管理器按全机归一化后的值。工作集包含共享/驻留页，私有内存是另一种口径，不能互换。

## 2026-10-06 本机样本

Windows 10.0.26300、12 个逻辑处理器、缩放 175%，Rust 1.98.1 Windows GNU，Slint 1.17.1 软件渲染，release 构建。为快速前后比较，本轮每阶段仅采样 3 秒，每个场景运行一次；长期空闲和多台机器尚未测量。

这次文字场景的空闲 CPU 样本为 0.54%–1.61% 单核心，展开面板为 0.59%–7.53%；带图场景两个阶段为 0%。较早一轮文字空闲样本也为 0%。短窗口内 CPU 计时粒度、光标闪烁、动画和系统负载会造成明显波动，不能据此承诺“零 CPU”。建议使用默认 8 秒以上窗口重复测量，长期体验再记录趋势。

## 缩略图复用的前后比较

相同机器、100 条记录、64 张相同规格模拟图片、相同 3 秒采样条件：

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 重开面板回调 | 135.60 ms | 9.33 ms |
| 收下并更新模型 | 134.49 ms | 4.45 ms |
| 展开面板工作集均值 | 39.69 MiB | 39.29 MiB |

原来的缓存超过 48 项后整批清空，导致每次模型同步都可能重新解码整组图片。现在以附件路径复用当前模型持有的缩略图，并在列表重建期间保留这些引用。优化后首次建立模型解码 64 张，重开和再收下一条文字记录均新增 0 次图片解码。现有独立缓存仍有 48 项上限；模型本身持有的图片内存另计。

这项改善针对已有缩略图的重复操作，首次启动仍需要解码图片。回调计时不包含完整的鼠标输入、Windows 合成和屏幕呈现链路，也不等同于用户感受到的端到端延迟。

## 验证边界

此入口测量 Slint 界面、存储与侧栏逻辑，省略正式应用的托盘、快捷键线程、拖放注册和周期提醒调度。因此数据适合比较场景与优化前后变化，不能替代正式程序长期运行的整体测量。截图不是桌面最终像素的证明，多屏、输入法、睡眠恢复等仍需按 [验收清单](VALIDATION.md) 实际体验。

当前工具链未安装 Clippy，本轮没有运行其静态检查；格式、编译、单元测试与渲染回归另有实际结果，不能把它们写成 Clippy 通过。
